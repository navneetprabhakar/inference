## Proposed pipeline and grouping contract

1. Freeze a new policy/code/input manifest before reading candidate contents. Pin both raw files and receipts, v3 DB/manifest/verification/custody, v3–v6 substantive rejection IDs/reviews, all historical train membership and holdout fingerprints supplied by the authorized custodian, public development protection and current source revisions. Rehash full source files before extraction. Never infer untouched from absence in one candidate DB.
2. Preserve every full raw conversation, original role/text order and publisher system instruction. No prefix truncation, answer rewriting, removing greetings from training text, replacement samples or new generated dialogue. Whole-history framing failure rejects that history under current runtime limits; a future larger context needs its own policy.
3. Before assigning any fresh split, independently review complete histories into **canonical substantive scenario + requested operation** groups. Read beyond greeting: e.g. changing an appointment time versus asking how to schedule an appointment are distinct; superficial names/wording variants of the same scenario are one group. Broad topic tags alone (food/travel) are insufficient. Record supporting user-turn indices, task intent, shared fact schema, correction/recall events, reviewer rationale and immutable review hash. Unknown or ambiguous group relations quarantine rather than invent independence.
4. Merge equal canonical keys, exact complete-history duplicates and high-overlap full-history variants into connected groups. Proposed lexical additional merge: five-word shingles, at least8 shared, Jaccard>=.65 or shorter-history containment>=.80. This catches conservative lexical relations; it cannot prove semantic disjointness. Independently inspect all cross-split nearest-neighbor groups before acceptance. Template/fact-schema matches must also merge even if lexical threshold misses. Freeze the grouping registry, membership and salt before split selection.
5. A group touching protected/historical development, known-bad or unknown membership is quarantined from new train/dev. Any otherwise eligible group touching prior training remains train; **never old train→new dev**. Only positively established untouched groups may hash into new exposed development (prospective20%, group-level). Report insufficient development without rerolling. New dev is development, not a fresh final/private acceptance gate.
6. Root custodian screens complete histories plus their turns against all historical/private/public exclusions; this agent does not read those case files. New clearance is mandatory even for old custody survivors, because source/full-history/framing may differ. Treat old selected-prefix clearance as insufficient for an extended parent.
7. Quality review is separate from grouping/custody. Review every retained history for actual requested response, internally consistent copied facts, corrections remembered later, fabricated external actions and role correctness. Keep ordinary small talk and appropriate uncertainty; do not reject all non-tool conversation or manufacture correction/recall examples. Record capability coverage and zero-coverage categories honestly. Source may simply lack sufficient correction/copy evidence.
8. Only after independent review may a separate builder apply current policy/framing and produce source-row provenance, exact target masks and train/dev streams. No candidate build or packing is authorized by this draft.

## Bounded implementation proposal

`grouping_draft.py` is a pure caller-supplied-record helper with no file/network/model imports. It requires complete-history hashes, explicit historical status and reviewed canonical task keys. It returns only a pending split proposal; it cannot grant eligibility. Proposed first candidate inspection is at most1,130 existing raw rows, one CPU thread/nice10, ten minutes,512MiB RSS,50MiB new output,20GiB disk floor, global/local STOP. No downloads or model execution. Before execution add the bounded file adapter, freeze exact pins and independent semantic registry review; do not reuse frozen v3 first-user family logic.

Available count is **770 train-reconsideration upper bound +319 unresolved raw rows**, not1,089 cleared examples. No genuinely untouched development count is established yet. If all substantive groups intersect prior train/holdout or fail fit/quality, this source supplies no new dev; use a separately acquired public source with prospective grouping rather than recycle old train.
