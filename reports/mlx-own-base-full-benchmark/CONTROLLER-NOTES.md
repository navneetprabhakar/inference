# Prospective controller clarification and integration

This adds implementation details to the existing reviewed feasibility protocol without changing historical receipts. It does not authorize a GPU launch or migration.

The controller holds the canonical GPU lock across sequential subprocesses. Existing own_base_dev_run owned-child watchdog/FIFO tickets enforce deadlines, process-group isolation and bounded TERM/KILL/reap. Each worker consumes the inherited ticket and binds its phase/spec SHA/parent. No automatic retry is enabled (the original protocol allowed at most one). Failure, partial work, resource exhaustion or failed numerical comparisons stops the entire comparison; retained evidence is not overwritten.

Total controller monotonic wall from before validation is capped at180minutes, conservatively including CPU verification, setup, interprocess gaps and cleanup. A separate six-hour wall/calendar check remains. Worker ledgers also charge elapsed time by period: correctness45minutes, warmup15total/max5per runtime, measured90total/max30per runtime, resume15 and overhead15. The controller's conservative outer cap cannot be expanded by omitted worker time. Attempts reserve against24,993,792targets before operations; commit follows actual synchronization. A pending attempt is never refunded and prevents subsequent phases.

For each sustained comparison, the measurement interval is a prescribed1800seconds from a recorded monotonic start. Stop dispatching new work before its end with a conservative remaining-time runway; any update actually crossing the measurement boundary fails the timing gate and is not relabeled completed inside it. Record the actual last commit offset. Transition budget accounting to overhead just before the boundary, wait through the fixed deadline, and report both prescribed1800seconds and actual observed span (which can exceed it slightly due to scheduling). The idle tail is included in the1800second throughput denominator. This avoids fabricating exact elapsed equality or reporting only a fast partial interval. Warmup10updates minimum, source restore, two settling updates and2048total source-update slice remain unchanged.

Root accepted the installed MLX0.32.4 limitation: its API exposes active/cache/peak memory but no driver-memory getter. Record driver null, explicit unavailable reason and installed version. This is optional telemetry only; missing active GPU memory or mandatory RSS/swap/thermal/disk/STOP/AC guards stops execution. Active GPU allocations>=12GiB stop; RSS>18GiB or swap growth>1GiB on two30-second samples stop; serious thermal state, unavailable mandatory telemetry, loss of AC or free disk<20GiB stop. RSS and GPU allocations overlap and are never summed.

All artifacts live inside the new benchmark run. Preflight admission requires the existing4GiB transient forecast and20GiB free floor. Each worker forecasts its write size including atomic temporary storage and re-verifies protected source before deleting only explicitly disposable reference/native artifacts. Phase result, watchdog and global ledger hashes form the evidence chain. Original checkpoints remain protected.

The executable phase order is generated/validated by expected_phase_plan(), not by comparing a spec field with a duplicate of itself. The externally reviewed exact spec SHA is the freeze. Worker source verification and every exact tolerance remain mandatory. Code/package/data identities are pinned prospectively; no package changes are permitted. The controller preparation itself never loads model/checkpoint tensors.
