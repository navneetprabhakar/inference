# Diagnostic-only data admission

Admit the three fixed, verified aligned datasets for a prospectively bounded own-base SFT diagnostic and its hardware preflight. This decision permits using the prepared teaching data; it does not activate a job, select a source repetition ratio, authorize a budget increase, or certify a usable model. The selected own-base parent, runtime hashes, resource limits, preflight and actual launch specification remain separate requirements.

Teacher-forced validation and data consistency checks do not establish generalization or conversation quality.

Keep train and validation/exposed-development streams separate. Never train on either protected acceptance gate, compiled development rubrics, public conversation development, or resulting model evaluation outputs. Future intake must include the newly frozen public-development exclusions. Actual source passes, repetition counts and compute costs must be explicit in the later launch specification. Any failed usability gate leaves the full objective unfinished.
