# Structured tool-routing experiment

- **Model.** One CPU-trained lexical classifier selects ordinary prose, result recall, unit recall, an arithmetic operation, or conversion. A second CPU-trained lexical model ranks quantity and unit spans for each argument. The two linear models contain 56,566 parameters. The artifact occupies 389,389 bytes. With one GPT-2 small student the deployed total is 124,496,374 parameters.
- **Data.** Training used 7,165 distinct tool histories, 3,394 chat histories and 189 additional natural histories. The trainer verified the published ordered pool hashes and applied the frozen history exclusions before extracting labels. It trained from zero-initialized weights on CPU. The exact artifact and source-denylist digests are in `head.json`.
- **Host behavior.** The parser normalizes common English cardinals, decimal literals and aliases for the broker’s supported units. The learned ranker may point to an observed prior result. The host serializes the chosen name and arguments, validates the broker schema, enforces per-turn permission and dispatches the resulting proposal. Missing or out-of-range slots suppress dispatch. The reported margin is the difference between the two largest classifier logits.
- **Student behavior.** Ordinary answers use the supplied GPT-2 and the actual serialized exchange history. For a successful numeric result or a learned result-recall decision, the host places the observed value into a plain numeric-copy prompt for the same GPT-2. The student generates its answer greedily. A truncated or nonnumeric reply fails, and its raw output remains in the turn record. Unit recall is answered by GPT-2 from the conversation history. Each response records its decision, selected path, frame origins, copy prompt, trace and generated answer.
- **Scoring.** This is a separate product configuration. Score exact first-call choice and arguments, observed-result reporting, follow-up accuracy, abstention, and complete conversations. The raw GPT-2 protocol has its own scorecard.

## CPU observations

The fresh route-and-slot screen passed 8 of 10 cases. A rows-and-sockets multiplication question was routed to addition. A conversion that stated the desired unit first caused the source and target to be reversed.

On the immutable working-chat step-600 GPT-2, a synthetic recorded fixture returned 53 for an addition request. The learned head dispatched the requested operation, recalled the observed number without a second call, and used the actual 53 as the operand in a subsequent addition. The model failed to report 53, then correctly reported 59 after the follow-up call. A separate conversion correctly produced 250 grams in the broker, but GPT-2 emitted nonnumeric text. Both prohibited-tool requests had zero dispatches. These diagnostic examples were authored separately from the frozen scoring sets.

Run `python fit_fallback_head.py` to train, and `python verify_fallback.py` to reproduce the route screen. Supply `--weights FILE --sha256 HASH` to the verifier to run the end-to-end CPU transcripts. The runtime class is `fallback_chat.Chat`. Local evidence is in `runs/working-head-01/self-tests.json`.
