# Grounded curriculum diagnostic v1 — prospective, not activated

## Decision and hypothesis

Use the unchanged `own_base_sft_train.py` with three **new** aligned sources and the same verified `preserve-095` own-base endpoint. Run a new fixed one-pass diagnostic after independent data checks and a fresh hardware preflight on those sources. Do not continue from the failed SFT candidate through an unsupported parent path, overwrite existing data, alter the completed optimizer decision, or load pretrained student weights.

The working hypothesis is narrower than “more SFT fixes the model”: short, varied, explicitly grounded teaching may reduce generic rewrite/help boilerplate and teach complete observation-conditioned operations. The completed model failed all12public conversation sessions and all8four-call sessions. These failures include lack of basic relevance and fact use, not merely malformed syntax. A <=1M-target intervention is a diagnostic of learnability, not an adequate-pretraining claim. If it still cannot produce relevant connected short responses, another template tranche is not justified; clean language pretraining must be reconsidered.

## Content construction

Use a small typed task/state representation with a separate natural-language renderer and answer verifier. Freeze semantic families, wording variants, lexicons and seed before generating instances. No model-generated free factual knowledge is needed: task facts are supplied in the prompt; tools produce actual observations. Local synthetic teaching does not change student random-init lineage.

**Chat:** allocate training-target shares prospectively across six groups:25%brief real request fulfillment (drafting, constrained suggestions, a short explanation using supplied facts);20%entity/relation questions;15%changes and corrections over2–4turns;15%faithful short transformations preserving supplied details;15%missing-input clarification followed by fulfillment;10%acknowledgment/recall/exact-format follow-up. These shares are engineering hypotheses, not a claim of optimality. Ordinary requests must actually receive usable content: do not teach asking for text when already supplied, generic offers of help, repetitive “changes made” paragraphs, invented external actions or unsupported facts. Typical prose answers should be8–64tokens; exact acknowledgments can be shorter. Some answers require two connected sentences so success cannot be achieved exclusively by scalar copying.

Author at least48training semantic/linguistic families and16new-development families across these groups, with multiple independently written surface forms. A family contains every paraphrase, entity/value substitution, reversed relation and correction variant of its underlying construction. Use fresh scenarios and entity dictionaries authored without copying evaluation prompts, names, numeric assignments or answer strings. Random lexical substitutions alone do not establish transfer. Preserve a modest range of sentence structure and answer phrasing while keeping every answer directly supported and short. Avoid using the current public evaluation's scenarios as the family inventory.

**Primary tools:** cover direct one-call and two-call chains, both arithmetic and conversion; balance operations and operand order. Include concise nonnumeric questions, missing operands, denied tools and arithmetic errors. An independent `FixtureSession` must execute each allowed operation; later arguments use the returned value rather than recomputing an ideal result. For synthetic recorded-observation counterfactuals, preserve their explicit provenance and verify using replay behavior rather than mislabeling them actual tool execution. Include contrastive records differing only in one supplied observation/operation/operand so copying a frequent result cannot satisfy both. Exact train/dev call signatures and parameter tuples must be disjoint.

**Four-call role:** generate complete2+2call sessions, then a third turn split across short original-fact recall, concise observation recap, and correction-without-recalculation. Earlier extension data admitted only29training histories and refused the long recap/recall versions; shorten **newly authored answers prospectively**, not old refused examples retrospectively. Keep all four actual records and full history. A third-turn final answer should be1–2short sentences and preserve the original input/final-observation distinction. If the full history cannot reserve256replytokens, refuse it. Do not fabricate targets above position767 or claim longer-context competence from a successful preflight. Qualify the retained source as four calls, final turn2 before the existing preflight can accept it.
