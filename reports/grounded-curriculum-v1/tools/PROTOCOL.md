# Grounded tool candidate construction v1

Candidate-only CPU construction, not training admission or packed data. PLAN.json and templates.json fix source ceilings, groups, seed, family splits, instance counts and wording before generation. The builder snapshots their hashes and all serializer/tokenizer/broker dependencies into policy.json before instantiating lessons. No private or existing development files are read by the builder. Root custody must additionally exclude newly exposed prior evaluation material and historical holdouts before any final packing.

Each semantic instance records its source family, kind, parameters, variant, chosen wording, operation plan, answer rules, actual tool proposals and stable observed records. Allowed operations execute FixtureSession. Synthetic recorded numeric or error fixtures are explicitly marked by that broker and bound to their proposal; ordinary results are not relabeled. Denied-tool requests teach no proposal. Complete histories use the existing Lesson-shaped JSON and unchanged adapt_lesson/last_turn_row, preserving host framing and a256-token reply reservation within1024context. Any fit failure rejects the whole lesson; no truncation, shortened retry or adaptive template edit occurs.

Primary fixed pools cover26training and16development wording/construction families across six capped groups. Every family includes its operator/operand/observation contrasts and two authored surface forms. Concepts such as arithmetic overlap by necessity; split wording/family separation is not claimed to establish independent semantic concepts. The four-call pool has eight training and four development construction families with distinct frozen operation compositions. Each contains all three third-turn tasks: original/final fact recall, four-observation recap, correction without recomputation. First and second turns each make two actual calls; the third is no-call. Answers are newly authored concisely before fit, not shortened versions of rejected old examples.

Selection scans the complete fixed pool in hashed order per source/split/group. Whole-history fit and cross-split complete-call/parameter-tuple rejection precede the target ceiling. At the first eligible lesson that would exceed a group's target cap, close that group permanently; unused targets remain unused. There is no cap redistribution, new pool generation, post-custody refill or selection using development outcomes. All candidate/refusal counters and attempted lesson identities are retained. Training and development caps are computed after actual framing including calls/EOT. Full call signatures and numeric parameter tuples are disjoint across retained splits; exact history duplicates are rejected.

The output SQLite documents table retains original_lesson_json and all compatible custody fields plus task_json. No input/label streams or diagnostic admission receipts are written. The authoring self-checks validate real broker record agreement and simple numeric/support invariants only; semantics_verified remains false pending separately implemented verification. Root must independently inspect every authored surface form, interpreter/state transitions, counterfactual provenance, masks/prefix fit and split/custody exclusions.

Resource bounds are fixed in PLAN.json. STOP, free-disk, wall-time, RSS and source-output caps apply. A source failure leaves partial output with its failure explicit; no automatic retry or in-place overwrite is allowed.
