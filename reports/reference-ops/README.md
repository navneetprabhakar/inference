# Referenced arithmetic in the preview

The optional preview arbitrates before legacy recall. A supervised, closed-set CPU pattern classifier learns the operation and operand order from 34 cleared teaching rows. Deterministic preprocessing recognizes one reference to the latest event and one explicit numeric operand. A validated proposal uses the actual latest recorded result. Only the host fixture executes arithmetic. An unsupported legacy numeric recall now requests clarification, unless the separately accepted readback head selects a trace field. The origin for a new call is `learned-reference-pattern/typed-serialization`; its answer is `host/observed-number`. No-call turns and absent or failed reference events return an explicit host abstention.

First-use internal evaluation accepted 12/18 positive questions, all correct, covering six operation/order classes. The other six sentence structures abstained. None of 18 negatives activated the new classifier. The 12 claimed forms produced 36 verified calls across three bound histories including a counterfactual result. All 43 integration checks passed, including failure, prohibition, quota, and readback. These tests exercised the real runtime, accepted heads, frame builder and fixture, with a byte tokenizer and stand-in model. A harness adapter initially returned a list instead of a tokenizer encoding and stopped before any scores were obtained; only the test adapter was corrected.

This is a learned typed-pattern table, not general arithmetic language understanding. Numeric percentages, multiple operations and older references are outside the selector's scope. Negatives measure extra captures by this classifier; legacy behavior on delegated ordinary inputs depends on the other preview components.
