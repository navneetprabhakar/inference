# Own-base SFT and runtime readiness

The standalone `own_base_sft_train.py` / `own_base_sft_control.py` implementation is prepared, not launched. It requires the completed selected optimizer endpoint, verified own random-init lineage, explicit source admissions, immutable budgets and matching hardware-preflight evidence. No pretrained student weights or alternate answer models enter this path.

Root and independent review reran 15 tiny CPU tests covering masked loss/padding, proportional source-update scheduling, atomic attempted-compute accounting, checkpoint rollback without refunds, optimizer/RNG resume, source split provenance and STOP handling. Independent review found a shared-lock bypass through nested run paths. The corrected entrypoint now requires a spec-bound canonical direct child of `ROOT/runs` and rejects aliases/symlinks before evidence loading. The corrected trainer SHA is `647d2f1363fa41c9cc447e6bfea698c517895fbffda2ff3afdb0c833647b3200`.

Training source updates are distributed over the full schedule according to frozen source passes. This avoids exhausting the smaller tool queue early and leaving a long conversation-only tail. Assistant targets, actual input positions, padded positions, attention cells and evaluation targets have explicit global and source ceilings; partial/replayed attempts remain charged. The actual source ratio, learning-rate schedule and production budget are not yet frozen.

Numeric equality and wording checks are intentionally conservative. Open conversation rubrics remain manual-pending until actual outputs are reviewed; no automated pass is inferred from teacher text.
