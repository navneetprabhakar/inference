Direct weight edits: no demonstrated conversation improvement

3 November 2026. All computation stayed on the laptop. No gradient training, paid API, cloud compute, original-checkpoint mutation or UI promotion.

Four fixed weight interventions were evaluated. None cleared the prespecified improvement gate. The best edited candidate tied baseline on complete development conversations; both checkpoints passed 0/40 complete conversations on the fresh holdout. This experiment does not establish a working assistant.

What was changed

  • rollback10: V11 + 0.10 × (100M foundation − V11), all tensors.
  • embed_norm25: V11 + 0.25 × (100M foundation − V11), tied input/output embedding and RMS norms only.
  • sparse_v15_50: V11 + 0.50 × largest-magnitude 20% of (V15 − V11), per tensor with deterministic ties. Trimmed task arithmetic, not full TIES.
  • clean_matrix25: V11 + 0.25 × (V18 − 200M foundation), attention/MLP matrices only.

All sources share model/tokenizer ancestry. All edited copies retain 97,536,768 parameters. Saved arrays were reloaded and verified; finite values, source hashes and BF16-effective changes were checked. CPU research, diagnostics and review ran in parallel; GPU inference was serialized to avoid memory contention.

The edit magnitudes relative to V11 L2 norm were 1.12%, 2.62%, 0.98%, and 1.34%, respectively. BF16-effective coordinate changes were 72.82%, 12.39%, 19.94%, and 77.89%. These percentages describe actual numerical changes, not percentages of learned knowledge.

Research and interpretation

  • Task arithmetic and TIES manipulate measured training deltas. They do not provide a map from an English instruction to hand-written competent neural weights.
  • WiSE-FT and model soups support interpolation experiments; their original vision evidence is not proof for this weak language model.
  • DARE assumes useful fine-tuning deltas; aggressive random deletion/rescaling was not justified by these checkpoint diagnostics.
  • ROME and MEMIT target factual associations through measured activations and optimized edits. They do not establish broad conversation repair for a weak 97.5M model.

Approximately 87% of squared drift from the original 100M foundation sits in the tied embedding. Rolling it back did not improve complete conversations on development. That rejects this particular repair, not every possible embedding intervention. Correct calculator calls followed by fabricated answers show that argument generation and result grounding remain separate failures. Penalty changes cannot supply missing comprehension.

Decision and next useful experiment

  1. Do not promote any edit or continue coefficient sweeps on these now-exposed cases. The adaptive gate required at least two extra complete development conversations without tool/no-call regression; none qualified.
  2. Keep V11 only as the reproducible, unreliable reference. This negative result does not prove that all weight-editing methods fail; it establishes that these four measured hypotheses failed.
  3. For the next authorized work, prioritize a contrastive learning diagnostic: same question structure with swapped names, numbers, negation and changing tool results. Require exact copying/result grounding and success on withheld variants before broad SFT. If it cannot learn this controlled task, investigate tokenization, loss masks, optimization and foundation capability before producing more dialogues.
  4. A useful general assistant under 200M parameters will likely need substantially stronger pretraining or pretrained initialization plus carefully supervised distillation. That is a separate change to the original from-scratch requirement, not a silent replacement. Deterministic tool-result rendering can improve a product, but must be reported as runtime behavior rather than neural accuracy.
