# Teacher cache to registered host transcripts

Creator: Navneet Prabhakar

## Delivered

- `slm.teacher.bridge` composes verified cached CLI demonstrations into plain continuations or typed tool conversations. It never initializes a CLI provider, reserves requests, changes journals, generates text or grants training approval. Cache reads use SQLite read-only mode; absent, uncertain and corrupt entries fail without a new request.
- Request, scenario, controls, model recipe, response, usage, schema and candidate bindings are checked against the completed cache entry. Historical v1 schema-array ordering is validated without reconstructing a different request key. V2 requires the submitted-prompt hash. For the oldest v1 record, that historical hash remains explicitly unavailable; the reconstructed hash is separate evidence.
- Each transcript includes visible style/content controls. Typed transcripts use the same discovered host schemas/header as `run_turn`. Historical plain assistant messages are wrapped as typed answers with empty fact objects; their text is retained and excluded from direct loss under `last-user-turn-v1`. Wrapping is not an endorsement of old claims.
- Teacher `multiply_amount` maps explicitly to registered `arithmetic(operation=multiply, left=unit_price_minor, right=quantity)`. A bounded local host executes the call. Its correlated result and a final typed answer are composed; the structured total must match the mock oracle. Unsupported tools, host-bound violations, inconsistent quantities and plain-mode tool exchanges are refused. This is one mapped tool, not general tool-schema adaptation.
- Clarifications identify explicitly unknown fact fields. Answer/no-tool, correction, style-pair and student-correction records are supported. Input context must end in a user turn and alternate plain user/assistant messages; partial historical tool exchanges are deliberately refused because their continuation boundary needs a separate contract.

## Provenance and publication

- A preview has no fabricated source license and stays `training_eligible=false`. Receipts bind the original record/request/response/scenario, teacher recipe, composed messages, family, host registry/context, result mapping, wrapper count and supervision boundary. Legacy tool replies carry an explicit ambiguity flag; a v2 prompt is also not proof that its prose is correct.
- Declared derivative parents require a verified reviewed release. Each parent must actually be an approved training member of the declared family; sample-only data, held-out identities and missing parents fail. Parent record/source/license and release hashes are retained. This proves membership/lineage checks, not that a supplied context semantically represents its parent.
- Sample snapshot export requires a caller-supplied source descriptor with pinned actual card/terms bytes and CLI origin. It copies the evidence, applies existing curation/family splits and publishes atomically as **sample-only**. No partial corpus is emitted if records disappear or privacy/normalization changes composed text. No source evidence or terms approval was invented for the actual candidates.
- The existing human publisher now additionally requires explicit teacher decisions for reply meaning, style/content, history conversion and host grounding. Generic English/privacy/quality approval alone fails. Controlled teacher content settings cannot be relabeled during release. The checked train reader rechecks these gates and composition receipts; structured host totals are independently recomputed.
- The existing public-source HTML console does not support those additional teacher decisions and refuses teacher packets instead of dropping fields. Teacher review currently uses the extended JSON packet generated by `slm.data.review prepare`. The private Markdown worksheet is a reading aid, not an accepted release authorization.
- These are hash-bound records and explicit attestations, not signed proof of authorship, actual human judgment or legal clearance. Source/category rights still require the stated evidence and review.

## Commands

Preview one existing cached demonstration without supplying source-rights evidence:

```sh
.venv/bin/python -m slm.teacher.bridge \
  --record data/teacher/broader-pilot-v1/result-tool_trajectory-professional/record.json \
  --journal data/teacher/cli-pilot-v2/journal.sqlite \
  --output /absolute/path/to/a-new-preview.json
```

Add `--source-record /absolute/path/to/pinned-source.json` to emit a sample snapshot directory instead. The descriptor uses the existing `slm.data.build.read_source` schema (`Source` fields plus relative `evidence_files.card` and `evidence_files.license`). Supply actual evidence, not placeholders. Use `--parent-release` for derived records with declared parents. Then prepare the ordinary review packet, complete its additional `decision.teacher_review` fields, and use the unchanged release/token-shard commands. A plain snapshot requires `--format plain`; tool trajectories require typed output.
