## Tokens and document provenance

New `slm.data.prose_research_tokens` uses the existing BPE, `Writer`, `ShardBatches` and common `verify_leaf` content reconstruction. It retains the frozen 16K tokenizer and portable batch layout. No role-serializer or model backend change is introduced.

Each complete prose document is encoded with EOS. Documents are concatenated and packed into causal foundation contexts, with all next-token targets supervised. **Cross-document attention is intentionally allowed**, as in the existing foundation pipeline; this is not whole-dialogue SFT or attention-isolated prose. The very first stream token is an input without a preceding prediction target, explaining the one-position difference between encoded and predicted counts. No document truncation, implicit repeat, source filtering or assistant-role fabrication occurs.

Each lineage row preserves original document/source/split identities, raw-record hash, source URL, crawl, upstream file path, published language/educational scores and token metadata, plus exact target-position start/end offsets. Upstream token counts remain source metadata; actual student counts are independently computed with this tokenizer. These spans enable later physical exposure accounting but do not themselves implement a global gradient-exposure ledger.

`verify_tokens` reopens the checked release and common portable batches, invokes the existing full source-token/mask reconstruction, and separately verifies upstream metadata, raw hashes and contiguous target spans. Rehashing a forged binary or changing a provenance URL in lineage cannot pass simply by updating the outer file manifest.

The category remains **unreviewed** in records and token metadata. A new research-admission receipt explicitly records private residual-risk use; it does not change the source to individually approved/SFW or certify content. The policy still has `training_ready:false` and permits only local MLX/CPU preparation and separately gated research execution; no CUDA/main-budget permission follows.
