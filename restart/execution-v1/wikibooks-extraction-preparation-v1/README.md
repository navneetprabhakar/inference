# Rendered Wikibooks extraction preparation

This is an offline, bounded extractor prototype. It has processed synthetic fixtures only. It has not established usable corpus counts or admitted any documents.

The official [Enterprise data dictionary](https://enterprise.wikimedia.com/docs/data-dictionary/) identifies Wikibooks as a textual project using the article model. It documents `name`, `identifier`, `url`, `version.identifier`, `article_body.html` and `license`. The [Snapshot guide](https://enterprise.wikimedia.com/docs/snapshot/) describes NDJSON records inside a compressed tarball and supplies a concrete record shape. These current docs guide validation; they do not prove the March 2025 artifact has an identical schema. Missing required fields cause a stop rather than alias inference, empty defaults or skipped records.

`extract.py` takes an existing input file plus its SHA256 and a new output directory. It contains no HTTP client. It streams tar members without extracting their paths. The default limits are 100 pages, 4MiB per record, 128MiB decoded input and 256MiB aggregate output. Hard preparation caps are 1,000 pages, 16MiB per record, 512MiB decoded input and 1GiB aggregate output. The decoded tar limit includes headers, padding and skipped contents; member declarations exceeding the bound fail. The output guard counts source records, SQLite files/journals and extracted evidence, reserves conservative space before database mutations and checks actual size after commits. It also preflights the output allowance plus a 20GiB free floor and the full 16GB planned weights reservation. A separate 16KiB output allowance is retained for terminal diagnostics. The source and extracted evidence are local only. The first schema mismatch or limit failure stops extraction and records `failure.json` alongside partial evidence; a missing success receipt is not a complete run.

The initial selection is an archive/line prefix, explicitly **not a representative sample**. Once the downloaded artifact exists and its recorded checksum has passed, a bounded inspection can establish its actual fields before a representative whole-book sampling design is frozen. Do not infer total page/token counts from this prefix. The prototype does not auto-discover or process arbitrary files.

Each output retains the original HTML string and hash, source record bytes/hash/location, page and revision IDs, title/URL, original structured license metadata and source metadata. Wikitext, if present, is preserved through the original source record and its hash. These are provenance records, not license clearance. The input remains authoritative; HTML extraction never rewrites it.

Book family IDs use NFC-normalized title text before the first slash. Root pages and subpages share a family. This is deliberately conservative and does not solve aliases, renamed books, translations, transclusions across books or broader near duplication. No main page/subpage concatenation occurs. Printable/complete-book aggregates are held. Within this bounded run, clean deeper chapters own repeated substantive blocks before root summaries; a later overlapping page is held as a whole rather than surgically deleting sentences. Unseen pages remain outside this duplicate check, so the output is not ready for split assignment.

Navigation and edit affordances are removed with an audit trail. Rendered template prose remains. Detected formula content receives a visible review marker and holds the entire page; tables also hold the entire page rather than treating flattened cells as coherent prose. Render errors, missing red-link dependencies, unexpanded markup, embedded media and detected visual dependence hold pages. Missing dependencies cannot be perfectly inferred from HTML alone: this is a conservative detector requiring representative semantic review, not an automatic quality certificate. Plain text outside structural paragraph/list/headings is not guessed into complete prose.

Run `python3 restart/execution-v1/wikibooks-extraction-preparation-v1/check_synthetic.py` for the synthetic checks. They cover schema/identity boundaries, formulas/tables/templates, navigation, family overlap, byte preservation and tar/line limits. They establish prototype behavior only. Any extraction after acquisition must record dependency versions, check actual schema, freeze sampling and review retained text before reporting usable counts.
